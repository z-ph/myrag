财务处制度知识库 RAG　　全栈开发（实验室）　　2026.08 – 至今
技术栈：React、Vite、antd、Zustand、Hono、PostgreSQL、LangChain.js、Qdrant、Redis、Docker
高校财务处文档管理与智能问答。独立完成 React 前端与 Hono 后端，工作重点是问答 Agent 的设计与优化。

· 设计单工具 Agent：将固定「先检索再生成」改为 LangChain createAgent，混合检索封装为 search_knowledge_base，由模型决定是否检索、如何改写 query、调用几次
· 优化多轮上下文：思考过程独立落库、不回灌下一轮；历史折叠为一条 user「问/答」回顾并剥离思维链，规避网关在流式下吞掉 reasoning
· 优化流式协议：用 streamEvents 并行推思考、工具调用与正文；SSE 的 data 一律 JSON 编码，修复换行和纯数字被拆帧丢失
· 优化检索结果：同轮多次工具调用按文档块去重，返回文本按上下文预算截断；工具轨迹与来源落库，刷新可回放

财务处制度知识库 RAG　　后端 / LLM 应用（实验室）　　2026.08 – 至今
技术栈：Hono、LangChain.js、PostgreSQL、Qdrant、Redis；前端 React + Vite + antd
制度问答服务。前后端独立交付，核心是检索工具化的 Agent 编排。

· 将混合检索（向量 + BM25 + MMR）收成唯一工具 search_knowledge_base，createAgent 每轮按需调用，闲聊可不检索
· 图片不进检索双路：视觉模型先结构化理解，OCR/摘要写入当前问题，再交给 Agent 决定是否搜库
· reasoning 与 content 分列存储，回灌只取正文；历史折成 user 回顾，避免思维链污染和网关丢思考
· 工具输出按预算截断、来源按 chunk 去重落库；生成取消本实例 Abort、跨实例走 Redis
