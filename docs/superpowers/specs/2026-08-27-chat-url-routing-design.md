# 会话 URL 路由与 404 页面设计

## 背景

当前聊天页只有 `/chat` 路由。前端通过 `myrag-current-conv` 从 `localStorage` 恢复当前会话 ID，并在身份变化后尝试清理该状态。访客 Token 重签、跨标签页登录或本地状态残留时，当前身份可能继续使用旧身份的会话 ID，服务端随后因归属校验返回「会话不存在」。

本次调整将 URL 设为当前会话的唯一来源。会话是否存在由服务端确认，不再通过浏览器本地状态推断。

## 目标

- 已有会话使用 `/chat/{conversationId}`。
- 新会话使用 `/chat/new`，首次发送前不写入数据库。
- 刷新页面或直接访问链接时，仅根据 URL 恢复会话。
- 会话不存在或当前身份无权访问时显示 404 页面。
- 移除当前会话 ID 的本地持久化与隐式恢复。

## 非目标

- 不修改会话 ID 的现有生成格式。
- 不改变消息生成、RAG 检索或 SSE 事件格式。
- 不允许不同身份接管已有会话。
- 不为会话增加公开分享能力。

## 路由规则

| URL | 行为 |
| --- | --- |
| `/` | 重定向到 `/chat/new` |
| `/chat` | 重定向到 `/chat/new` |
| `/chat/new` | 显示空白的新会话页面，不请求会话详情 |
| `/chat/{conversationId}` | 请求会话详情；存在时显示消息，不存在时显示会话 404 页面 |
| 其他路径 | 显示通用 404 页面 |

应用部署在非根路径时，以上 URL 继续由现有 `BrowserRouter basename` 处理。

## 状态归属

### URL 状态

`ChatPage` 从 React Router 参数读取 `conversationId`。`/chat/new` 表示新会话，`/chat/{conversationId}` 表示已有会话或首次发送期间正在创建的会话。

URL 是当前会话 ID 的唯一来源。以下内容不再保存在 Zustand 或 `localStorage`：

- 当前会话 ID
- 上次打开的会话 ID
- 身份变化前的会话位置

消息、生成状态、会话列表和临时文档引用仍可保存在 Zustand，但所有需要操作会话的动作必须显式接收 `conversationId`。

### 身份变化

登录、退出或访客 Token 重签完成后，页面导航到 `/chat/new`，同时清空当前消息和生成状态。身份变化不读取或恢复旧会话 URL。

不同标签页引起的身份变化不应让当前页面继续向旧会话发送消息。后续实现至少需要监听相关身份事件并导航到 `/chat/new`；跨标签页 Token 同步可通过 `storage` 事件完成。

## 新会话流程

1. 访问 `/chat/new` 时显示空白聊天页。
2. 首次发送时由前端生成会话 ID。
3. 使用 `replace` 导航到 `/chat/{conversationId}`，避免后退时回到已消费的 `/chat/new` 草稿页。
4. 使用同一个 ID 调用消息创建接口。
5. 服务端按现有懒创建规则创建会话并保存消息。

首次请求在会话写入前失败时，当前 URL 可能暂时指向尚未创建的 ID。页面内允许直接重试发送；若此时刷新页面，详情接口返回 404，并显示会话 404 页面。前端不得把该 ID 静默替换成另一个会话。

## 已有会话流程

1. 访问 `/chat/{conversationId}`。
2. 页面请求 `GET /conversations/{conversationId}`。
3. 请求完成前显示加载状态。
4. 请求成功后渲染服务端消息。
5. 服务端返回 404 时渲染会话 404 页面。
6. 其他请求错误显示加载失败状态，并提供重试操作。

切换侧栏会话时直接导航到目标 URL。浏览器前进、后退和刷新均重新按 URL 加载对应会话。

## 服务端接口语义

`GET /conversations/{conversationId}` 调整为标准资源语义：

- 会话存在且属于当前身份：返回 HTTP 200 和会话详情。
- 会话不存在：返回 HTTP 404。
- 会话属于其他身份：返回 HTTP 404，避免泄露资源存在性。

服务层可继续使用带 `exists` 的内部查询结果，但路由层不得再向前端返回 `HTTP 200 + exists:false`。成功响应中的 `exists` 字段可暂时保留，以减少无关的类型改动；前端不再依赖该字段判断 404。

`POST /conversations/{conversationId}/messages` 保留现有归属校验。不得通过转移会话归属或忽略 `userId` 差异处理 404。

## 页面与交互

### 会话 404 页面

会话 404 页面显示在现有应用外壳内，包含：

- 状态码：`404`
- 标题：`会话不存在`
- 说明：`未找到对应会话，或当前账号无权访问。`
- 操作：`新建会话`，进入 `/chat/new`

### 通用 404 页面

未知应用路径显示通用 404 页面，不再自动重定向到聊天页。页面提供「返回首页」操作，进入 `/chat/new`。

### 会话列表

- 点击历史会话：导航到 `/chat/{conversationId}`。
- 点击「新建会话」：导航到 `/chat/new`。
- 删除当前会话：删除完成后导航到 `/chat/new`。
- 删除非当前会话：保持当前 URL 不变。

## 错误处理

- HTTP 404：显示会话 404 页面。
- HTTP 401：沿用认证恢复流程；身份恢复后进入 `/chat/new`。
- HTTP 500、网络错误或超时：显示加载失败状态，不显示 404。
- SSE 生成错误：保留当前 URL 和已显示消息，允许在同一会话重试。
- URL 中的会话 ID 不符合服务端参数约束：按会话 404 处理，不自动生成新 ID。

## 代码边界

### `App.tsx`

- 声明 `/chat/new` 和 `/chat/:conversationId`。
- 将 `/` 和 `/chat` 重定向到 `/chat/new`。
- 用通用 404 页面替换通配路由重定向。

### `ChatPage.tsx`

- 从路由参数读取会话 ID。
- 区分新会话、加载中、已有会话、404 和加载失败状态。
- 负责首次发送时生成 ID 和导航。
- 负责侧栏选择、删除与新建后的导航。

### `store/chat.ts`

- 删除 `CURRENT_KEY`、`saveCurrent` 和持久化的 `conversationId`。
- 会话操作显式接收会话 ID。
- 数据仓库不负责导航，也不推断当前路由。

### `store/auth.ts`

- 身份事件只负责清理身份相关聊天数据。
- 页面导航由路由层响应身份版本或身份事件完成，避免状态仓库直接依赖路由对象。

### 服务端会话路由

- 详情资源不存在或越权时抛出 `notFound('会话不存在')`。
- 保留消息写入与取消操作的归属校验。

## 测试要求

### 前端路由测试

- `/` 重定向到 `/chat/new`。
- `/chat` 重定向到 `/chat/new`。
- `/chat/new` 不请求会话详情。
- `/chat/{conversationId}` 请求对应会话并显示消息。
- 详情接口返回 404 时显示会话 404 页面。
- 详情接口返回 500 时显示加载失败状态，而不是 404。
- 未知应用路径显示通用 404 页面。

### 前端交互测试

- 新会话首次发送时生成 ID，URL 以 `replace` 方式切换后使用同一 ID 发送消息。
- 点击历史会话后 URL 更新。
- 点击「新建会话」后进入 `/chat/new`。
- 删除当前会话后进入 `/chat/new`。
- 身份变化后清空消息并进入 `/chat/new`。
- 页面刷新时不读取 `myrag-current-conv`。

### 服务端测试

- 当前身份读取自己的会话返回 HTTP 200。
- 读取不存在的会话返回 HTTP 404。
- 读取其他身份的会话返回 HTTP 404。
- 越权消息写入仍返回 HTTP 404。

## 验收标准

- 地址栏始终明确表示新会话或具体会话。
- 刷新 `/chat/{conversationId}` 可以恢复对应会话。
- 浏览器中不存在 `myrag-current-conv` 的读写逻辑。
- 不存在或越权的会话显示 404 页面，不创建替代会话。
- HTTP 500 和网络错误不会显示为 404。
- 登录、退出和访客身份重签后不会继续使用旧身份的会话 ID。
- 服务端继续阻止不同身份写入同一会话。
